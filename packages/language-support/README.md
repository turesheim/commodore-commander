# Language Support

`@commodore-commander/language-support` owns TypeScript language logic,
machine/reference data and build planning. It has no Theia or Eclipse runtime dependency.

## Source and package entry points

- `src/**/*.ts` is the maintained source. Generated Langium TypeScript under
  `src/langium/generated` is committed and regenerated by the build.
- `dist/` contains compiler JavaScript/declarations and copied reference/syntax
  assets. It is ignored by Git; do not commit emitted JS, maps or declarations
  beside their TypeScript sources.
- The package root exports editor/domain APIs plus Node filesystem/project/build
  helpers. `@commodore-commander/language-support/runtime` is the browser-safe
  entry point used by Theia frontend consumers. Both exports resolve to `dist`.
- Preserved Java/ANTLR files in `reference/` are behavior references, not runtime
  dependencies. XML reference data and syntax assets are used by the product.

Build before consuming the package through its exports. Source tests import
TypeScript directly through Node's type stripping.

## Responsibilities

| Source area | Role |
| --- | --- |
| `document`, `location`, `resolution` | Text/position models, file-URI helpers, loading and include resolution |
| `semantic`, `parsing` | Tolerant expression/scope/import/directive model and a compatibility scanner facade |
| `langium`, `outline` | Structural Kick Assembler outline and SIDScore subtune/effect outline |
| `lookup`, `features`, `symbols` | Definitions/references, hover content, completion, rename, workspace symbols, semantic tokens, folding, formatting and quick fixes |
| `reference`, `machines` | XML mnemonic/C64 I/O data and typed machine/profile facts |
| `project`, `build` | Include graph, program/profile/run settings, standalone roots, generated assets and KickAss invocation planning |
| `syntaxes`, `language`, `runtime` | Grammar/configuration assets, language manifests and browser-safe exports |

Lookup binds project tokens to case-sensitive qualified names. Multiline
`.namespace` blocks support nested/reopened namespaces, parent/root fallback and
`@` root escapes. All declarations are collected before references, so supplied
document order does not control resolution. Rename replaces only the leaf name,
preserving reference prefixes; workspace symbols expose namespace containers.
Project symbols take precedence over reference symbols. Lookup filters hardware
references by active machine while sharing 6502 mnemonic data; hover content
preserves reference HTML. Machine profiles cover C64, C128, VIC-20, Plus/4, C16,
PET, CBM-II/5x0 and C64DTV.

Build planning resolves runtimes, library roots, output paths, machine overrides,
profiles, named runs and affected programs. It also models SIDScore-generated
assembly dependencies. Executing Java/KickAss or SIDScore processes belongs to
the Theia/headless runner; the language package plans those inputs.

## Limits

The semantic model and editor services are structural/name-based, not a full
KickAss compiler. Conditional branches are represented without evaluating a
configured symbol environment; macros/pseudocommands are not expanded.
Lexical block/label scopes, local/anonymous labels, `.filenamespace` and
import-site namespace context still need compiler-accurate lookup. Namespace
renames and ambiguous duplicate declarations are rejected; replacement names
are single identifiers. Diagnostics and reference datasets remain incomplete.

`KickAssemblerLookupService` caches project/XML analysis and the last assembled
index. Reuse requires identical ordered URI/kind/text/language inputs and active
machine; model versions alone do not invalidate it. `buildIndex()` returns
independent mutable maps, arrays and occurrences. Changed inputs trigger fresh
assembly using reusable document analysis; removed documents are evicted.
`clearDocumentCache()` releases all language lookup state.

Theia reuses file discovery and disk text models for up to five seconds, with
file/workspace event invalidation and current editor text overriding disk data.
Unchanged inputs reuse index assembly; per-document index updates and
include-graph-precise lookup remain work.
SIDScore has syntax/outline support, but no compiler-accurate TypeScript language model.
Debug metadata and VICE debugging belong to `debug-adapter`; Theia UI,
preferences and process orchestration remain outside this package.

See [language architecture](../../design-docs/language-support-architecture.md)
and the [status report](../../design-docs/ts-language-support-report.md).

## Verification

```sh
npm test --workspace @commodore-commander/language-support
npm run build --workspace @commodore-commander/language-support
```

Tests use Node's built-in type stripping. The build regenerates the Langium
outline parser, runs `tsc` and copies assets to `dist`. The generated-runtime
executable test is skipped when the local patched VICE package is unavailable.
