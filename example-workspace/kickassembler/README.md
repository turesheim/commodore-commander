# Kick Assembler Debugging Demos

Use `visual-debugger-demo.asm` to exercise the C64 Visual Debugger. It writes
screen codes and color RAM directly, installs sprite 0 bitmap data at `$2000`,
sets the sprite pointer at `$07f8`, and moves sprite 0 around the screen.

Useful labels to inspect while it runs include `sprite_x_lo`, `sprite_x_hi`,
`sprite_y`, `sprite_dx`, `sprite_dy`, `frame_counter`, and `Sprite0Bitmap`.

Use `debug-demo.asm` to exercise the Theia/Commodore Commander debugger.

## Visual Debugger Fixture

1. Open `example-workspace` in Commodore Commander.
2. Build `visual-debugger-demo` or save `kickassembler/visual-debugger-demo.asm`.
3. Start **Debug visual-debugger-demo in VICE**.
4. Open **View > C64 Visual Debugger**.
5. Inspect the Screen RAM, Character Memory, Color RAM, VIC-II registers, and
   Sprites tabs while sprite 0 moves.

## Prepare

1. Open `example-workspace` in Commodore Commander.
2. Open `kickassembler/debug-demo.asm`.
3. Save the file. The workspace auto-builds Kick Assembler sources on save and should produce `out/debug-demo.prg` and `out/debug-demo.dbg`.
4. Set breakpoints on the lines marked `DEBUG`.

## Start Debugging

1. With `debug-demo.asm` active, choose `Run > Start Debugging`.
2. If prompted to create a VICE launch configuration, choose `Create and Start`.
3. The generated launch entry should use:

```json
{
  "type": "commodore-vice",
  "request": "launch",
  "program": "${workspaceFolder}/out/debug-demo.prg",
  "debugInfo": "${workspaceFolder}/out/debug-demo.dbg",
  "sourceRoot": "${workspaceFolder}",
  "stopOnEntry": true
}
```

## Things To Try

- Stop on entry at `Start`, then step over `jsr MarkStepTarget`; execution should land on the following `nop`.
- Restart and step into `jsr MarkStepTarget`; execution should enter the `MarkStepTarget` subroutine instead.
- Step through `CopyMessage` and watch registers `A`, `X`, `Y`, and `PC`.
- Continue to `PulseLoop` and observe repeated breakpoint hits.
- Open the Variables view and inspect `6510 Registers` and `Kick Assembler Labels`.
- Edit a register value while stopped, for example change `A` or `X` before stepping.
- Evaluate labels such as `message`, `copy_index`, `current_color`, `frame_counter`, and `demo_state`.
- Open `View > Views > Memory` while stopped. Try the Screen preset with `C64 Screen` text rendering, then enter labels such as `message` or `scratch_value` as the address.
- Enter multiple memory monitors such as `$0400-$0427, message, scratch_value`.
- Edit a byte in the Memory view and press Enter or leave the cell to write it back through DAP `writeMemory`.
- Add a data breakpoint/watchpoint for a label such as `demo_state` or `current_color` from the debugger data-breakpoint UI.
- Use the disassembly view from a stopped frame to inspect generated code around the current PC.
- Use Pause while the program is in `Hold` to stop the emulator again.

## Notes

- Source breakpoints require the `.dbg` file generated by Kick Assembler.
- Breakpoints on data declarations may be unverified; put breakpoints on instruction lines.
- Conditional breakpoints and logpoints are not implemented yet.
